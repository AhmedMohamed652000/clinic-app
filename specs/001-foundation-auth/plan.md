# Implementation Plan: Foundation & Authentication

**Branch**: `001-foundation-auth` | **Date**: 2026-04-25 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-foundation-auth/spec.md`

---

## Summary

Establish the full project structure and implement authentication for all four user roles — Patient (Firebase phone OTP), Doctor (email + password, pending approval), Clinic (email + password, pending approval), and Admin (seeded credentials). Includes JWT session management, refresh token rotation, role-based route guards, admin verification queue, approval/rejection notifications via FCM + SendGrid, and Arabic RTL UI across Flutter mobile and React admin dashboard.

---

## Technical Context

**Language/Version**: Node.js 20 LTS (backend) · Dart 3.x / Flutter 3.x stable (mobile) · TypeScript 5.x (admin)
**Primary Dependencies**: Express · Mongoose · firebase-admin · jsonwebtoken · bcryptjs · Multer · SendGrid · flutter_bloc · Dio · go_router · React 18 · TanStack Query · shadcn/ui · Tailwind CSS
**Storage**: MongoDB 7.x (user data, tokens) · Firebase Storage (verification documents)
**Testing**: Jest + Supertest (backend) · Vitest (admin) · flutter_test (mobile)
**Target Platform**: iOS 15+ and Android 8+ (Flutter) · Modern browsers (React admin) · Linux server (Node.js)
**Project Type**: Mobile app (Flutter) + REST API (Node.js) + Web admin dashboard (React)
**Performance Goals**: Patient registration ≤ 3 min end-to-end · Admin approval ≤ 3 clicks · Approval notification within 60 sec
**Constraints**: TLS 1.2+ in transit · Documents max 10 MB · Access token 15 min · Refresh token 7 days · bcrypt cost factor 12
**Scale/Scope**: Phase 1 of 7 · ~4 user roles · ~15 Flutter screens · ~5 admin pages · ~20 API endpoints
